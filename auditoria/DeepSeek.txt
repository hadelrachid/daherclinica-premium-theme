### **1. Auditoria e Otimização de CSS (A Causa do 60% no Desktop)**

#### **Diagnóstico:**
O arquivo `assets/css/main.css` é grande (contém todo o CSS do tema). Embora esteja sendo minificado (`main.min.css`), ele é carregado de forma síncrona, bloqueando a renderização da página. No Desktop, onde a conexão é mais rápida, o navegador ainda precisa baixar, analisar e aplicar todo esse CSS antes de mostrar qualquer conteúdo ao usuário, o que causa o atraso no FCP.

#### **Solução Proativa: Critical CSS & Carregamento Assíncrono**

1.  **Extrair o "Critical CSS"**: Identificar e extrair as regras CSS necessárias para renderizar a parte visível da página (acima da dobra - *above the fold*). Isso inclui o header, o hero, e o início do conteúdo.
2.  **Injetar o Critical CSS no `<head>`**: Colocar esse CSS crítico dentro de uma tag `<style>` no `<head>` do HTML.
3.  **Carregar o `main.min.css` de forma assíncrona**: Carregar o CSS principal com a técnica de `preload` + `onload`, para não bloquear a renderização.

#### **Implementação no `inc/assets.php`:**
Substitua a função `enqueue_styles` para implementar essa estratégia.

1.  **Gerar o Critical CSS Dinamicamente (Recomendado):** É inviável manter um bloco enorme de CSS crítico manualmente. A melhor prática é usar ferramentas como `critical` (npm) ou o plugin **Autoptimize** com a opção "Inline CSS" ativada. Isso gerará o CSS crítico automaticamente para cada página.
2.  **Configurar o `style_loader_tag`:** Para garantir que o `main.min.css` seja carregado com o `media="print"`, já estamos fazendo isso. O navegador vai baixá-lo com baixa prioridade e, após o carregamento, ele será aplicado.

### **2. Otimização de Imagens (LCP no Desktop)**

#### **Diagnóstico:**
A imagem de herói (`hero.webp`) no Desktop tem resolução `1920x1080`, que é adequada, mas o tamanho do arquivo pode ser grande. Além disso, ela não está usando `fetchpriority` para indicar ao navegador que ela é a imagem mais importante.

#### **Solução:**
1.  **Atualizar o `template-parts/hero.php`** para adicionar `fetchpriority="high"` à imagem.
2.  **Otimizar as imagens no servidor (Build)**: Se você está criando o tema, use ferramentas como `sharp` ou `imagemin` para converter e comprimir as imagens `hero.webp` e `hero-mob.webp` para o tamanho exato que será exibido no navegador. Uma imagem de 1920x1080 deve ter menos de 150kb para ser considerada excelente.

```php
// template-parts/hero.php (Código atualizado com fetchpriority)
<img src="<?php echo $hero_desktop; ?>" 
     alt="Daher Clínica" 
     class="hero-image" 
     width="1920" 
     height="1080" 
     loading="eager" 
     fetchpriority="high" // <--- ADICIONADO
     decoding="sync">
```

### **3. Otimização de JavaScript (TBT)**

#### **Diagnóstico:**
O Google Tag Manager e outros scripts externos estão bloqueando a thread principal no Desktop, aumentando o TBT.

#### **Solução Proativa:**
1.  **Carregar o Google Tag Manager de forma mais inteligente:** No `footer.php`, o GTM está sendo carregado após 5 segundos ou na primeira interação. Podemos melhorar isso usando a API `requestIdleCallback`.

```javascript
// footer.php (Substitua a lógica existente)
<script>
    if ('requestIdleCallback' in window) {
        requestIdleCallback(function() {
            // Carrega o GTM quando o navegador estiver ocioso
            (function(w,d,s,l,i){
                w[l]=w[l]||[];w[l].push({'gtm.start':
                new Date().getTime(),event:'gtm.js'});
                var f=d.getElementsByTagName(s)[0],
                j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';
                j.async=true;
                j.src='https://www.googletagmanager.com/gtm.js?id='+i+dl;
                f.parentNode.insertBefore(j,f);
            })(window,document,'script','dataLayer','GTM-XXXXX'); // <-- Substitua pelo seu ID
        });
    } else {
        // Fallback para navegadores que não suportam requestIdleCallback
        setTimeout(function(){
            // Código do GTM aqui...
        }, 3000);
    }
</script>
```

2.  **Remover/Adiar o Font Awesome do render blocking:** Você já está usando `media='print'`, o que é ótimo. Certifique-se de que a técnica `onload` está sendo aplicada para que o Font Awesome seja carregado e aplicado após a renderização inicial.

### **4. Auditoria e Otimização do Banco de Dados (Módulo de Rastreamento)**

#### **Diagnóstico:**
O módulo `WhatsApp_Tracker` está gravando logs diretamente no banco de dados (tabela `wp_options`) para cada clique. Isso pode causar lentidão, especialmente em momentos de pico de tráfego.

#### **Solução:**
1.  **Substituir `wp_options` por uma Tabela Personalizada:** É muito mais eficiente usar uma tabela SQL dedicada para armazenar grandes volumes de dados de log. Isso evita o inchaço da tabela `wp_options` e melhora a performance.

```php
// inc/Services/WhatsApp_Tracker.php (Nova implementação com tabela personalizada)

public function create_table() {
    global $wpdb;
    $table_name = $wpdb->prefix . 'daher_wa_clicks';
    $charset_collate = $wpdb->get_charset_collate();
    $sql = "CREATE TABLE $table_name (
        id bigint(20) NOT NULL AUTO_INCREMENT,
        event_time datetime DEFAULT CURRENT_TIMESTAMP,
        device varchar(20) DEFAULT 'unknown',
        source varchar(50) DEFAULT 'unknown',
        PRIMARY KEY (id),
        KEY idx_event_time (event_time)
    ) $charset_collate;";
    require_once(ABSPATH . 'wp-admin/includes/upgrade.php');
    dbDelta($sql);
}

public function track_click(string $device, string $source): array {
    global $wpdb;
    $table_name = $wpdb->prefix . 'daher_wa_clicks';
    $wpdb->insert(
        $table_name,
        ['device' => $device, 'source' => $source],
        ['%s', '%s']
    );
    // Retorna um array vazio ou com dados para compatibilidade
    return ['status' => 'success'];
}

public function get_stats_for_month(string $month_key): array {
    global $wpdb;
    $table_name = $wpdb->prefix . 'daher_wa_clicks';
    $date_start = date('Y-m-01 00:00:00', strtotime(str_replace('_', '-', $month_key)));
    $date_end = date('Y-m-t 23:59:59', strtotime(str_replace('_', '-', $month_key)));

    $results = $wpdb->get_results($wpdb->prepare(
        "SELECT device, source FROM $table_name WHERE event_time BETWEEN %s AND %s",
        $date_start, $date_end
    ));

    // Processa os resultados para manter a compatibilidade com a interface
    $stats = ['total' => 0, 'mobile' => 0, 'desktop' => 0, 'sources' => []];
    foreach ($results as $row) {
        $stats['total']++;
        if ($row->device === 'mobile') $stats['mobile']++;
        if ($row->device === 'desktop') $stats['desktop']++;
        $stats['sources'][$row->source] = ($stats['sources'][$row->source] ?? 0) + 1;
    }
    return $stats;
}
```

2.  **Executar a criação da tabela:** Adicione `register_activation_hook` no `functions.php` para criar a tabela quando o tema for ativado.

### **5. Configuração do Servidor e Cache**

#### **Diagnóstico:**
A configuração do servidor (especialmente se for Hostinger) pode não estar otimizada para o máximo de performance.

#### **Solução:**
1.  **Cache de Página:** Ative o **LiteSpeed Cache** no painel da Hostinger ou o **WP Super Cache**. O tema já tem um botão para limpar o cache, o que é excelente.
2.  **Compressão Gzip/Brotli:** Verifique se a compressão está ativa para arquivos HTML, CSS e JS.
3.  **CDN:** Considere usar um CDN (como Cloudflare) para distribuir os arquivos estáticos, reduzindo a latência para usuários em outras regiões. **Não se esqueça:** Se usar Cloudflare, ative a opção *"Always Online"* e configure o *"Cache Level"* para *"Standard"* para não conflitar com o CSS crítico.
